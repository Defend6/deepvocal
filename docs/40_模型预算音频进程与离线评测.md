## 模型调用准入与账本

迁移 `0006_provider_budget` 新增 `model_budget_periods` 和 `model_call_reservations`。前者按上海时区月份汇总同一数据库/适配器的共享账户支出；后者保存每次调用的 owner/job、模型、费率快照、预占、实际usage或异常结算状态，不存Key与提示正文。系统CLI入库没有用户owner，同样消耗共享额度。

每次外呼按 reserve → dispatch → HTTP → settle 执行。并发预占锁预算行，数据库约束已结算与占用总额不超过本地月额度；同月已有额度不自动提高，降低配置仅在现有承诺可容纳时生效。自动跨月使用新周期，旧周期未结调用继续占用旧周期。当前仅支持人民币分，未实现日预算、多币种或供应商账单自动导入。

`.env` 需显式设置：

| 配置 | 含义与默认行为 |
|---|---|
| `MODEL_API_KEY` | 私有Key，缺失时禁止调用 |
| `MODEL_MONTHLY_LIMIT_MINOR=0` | 月额度，单位人民币分；默认0禁止付费 |
| `MODEL_BILLING_VERIFIED=false` | 人工核实下述计费假设后才设true |
| `MODEL_PRICES_JSON={}` | 精确模型名索引的JSON，每个模型包含 `input_minor_per_million`、`output_minor_per_million`，均为“人民币分/百万tokens”的非负十进制字符串 |

例如供应商每百万输入tokens收1元，应填100分，不能填1。这里不填写任何模型的实际价格，避免把示例误当最新费率；embedding、reranker、chat三个模型都须核对。若供应商按字符、请求次数、隐藏推理tokens或其他规则收费，必须先调整适配器与核账规则，不能直接勾选已确认。

目前以UTF-8请求JSON字节数+1024估计输入token上界；聊天输出最多900tokens；按配置费率以Decimal向上取整到分。这是需按实际供应商验证的保守计费假设，不能证明任意模型实际账单上限。正常usage在上界内按usage结算；缺usage、HTTP失败或不确定费用按预占上界记账。usage超界则保守扣预占并暂停该周期新调用，保留异常待核账。服务崩溃或结算数据库失败留下占用，不自动退款。取消发生在reserve之后也可能留下未发出请求的占用，需人工核账。

有job的调用在reserve与dispatch前检查owner、RUNNING、未取消、租约、worker token和版本；令牌通过运行时闭包传递，不写入LangGraph checkpoint。失效或取消任务禁止后续新调用。数据库dispatch提交与外部HTTP发送无法构成原子事务：检查后到发送前仍有竞态，已发出的请求不能撤销；重试也不承诺供应商侧exactly-once，可能再次收费。每次尝试均重新占预算。

模型响应限制8MiB，端点只允许 `/embeddings`、`/rerank`、`/chat/completions`；错误正文不返回用户。真实模型尚未联调，缺少Key不会生成假答案或向量。

```powershell
# 在项目根目录运行；只读检查，不调用供应商、不打印Key
.venv\Scripts\python.exe -m app.model_cli check
.venv\Scripts\python.exe -m app.model_cli status
```

check缺配置以退出码1返回；status只读本地账本与待核账记录。没有自动释放费用的按钮，不能猜测退款；需要先核实供应商账单和未完成进程，制定可审计的核账迁移后处理。`GET /v1/model/usage` 和前端费用面板只显示当前身份汇总；账户总预算不通过用户API暴露。上述约束只覆盖本数据库中的适配器调用，共享同一Key的其他程序支出不受控制。供应商侧额度应独立设置。

## 音频执行隔离

音频解码、F0及评分在独立Python进程运行，默认wall deadline90秒、内存1536MiB。Windows使用Job Object限制进程内存/活动进程数；Linux使用RLIMIT_AS、CPU、输出文件大小和禁用core dump。Windows的CPU时间不单独限额，靠父进程wall deadline终止。加载native codec之前设置限制，安装失败则不测量。

父进程异步轮询；正常退出、超时、异常或任务取消均回收子进程并清除临时音频/结果，测试覆盖真实进程与故障注入。子进程环境白名单不包含模型Key、数据库连接或.env路径，临时目录在 `runtime/audio/`，Docker在 `/app/runtime/audio/`。可配置 `AUDIO_PROCESS_TIMEOUT_SECONDS`、`AUDIO_PROCESS_MEMORY_MIB`、`AUDIO_RUNTIME_ROOT`。

这是资源受限进程，不是完整文件系统或网络安全沙箱；子进程仍沿用操作系统账户权限。强制杀死父进程/主机断电不属于finally清理保证，需后续清理遗留私有目录。真实不可信音频公开服务仍需更强的容器权限、网络和磁盘隔离。仅预签名资产保持pending，不能通过这个实现自动成为ready。

## GraphRAG 离线冒烟基准

`fixtures/knowledge-smoke-v1.json` 包含24条检索问题与相关chunk标签，以及8条无Key、无证据、健康拒答、提示注入输入的边界案例。案例派生于12条原创研究种子，未经专家审核，也不是独立测试集。

```powershell
.venv\Scripts\python.exe -m app.knowledge.cli prepare
.venv\Scripts\python.exe -m app.knowledge.evaluate --cases fixtures/knowledge-smoke-v1.json --output _qa/knowledge-smoke-v1-result.json
```

评测强制清空模型Key，报告词法hit@1/5、MRR、每条检索结果与边界结果、语料指纹、案例哈希，模型调用数为0。未知chunk标签或重复案例拒绝执行。CI要求边界全部通过且hit@5至少0.9。

本轮运行24条词法检索hit@1/5与MRR均为1，边界8/8通过。该结果只说明这些种子派生冒烟用例通过；提示注入案例只验证无Key不生成答案，不能证明真实模型抗注入。报告显式标记 `expert_benchmark=false` 与 `hybrid_retrieval_evaluated=false`。没有测量真实embedding、图检索融合、reranker、回答语义、教师认可度；不能与原图82.7%比较，也不能据此宣传专业准确率100%。
