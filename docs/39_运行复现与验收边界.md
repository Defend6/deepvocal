## ADR：实际合同与完整设计并存

完整设计保留 `contracts/openapi.json`、`database/schema.sql`、01～29章及其历史设计审查结果；实际接口独立导出为 `contracts/runtime-openapi.json`，数据库以 Alembic `0001`～`0005` 为准。禁止直接运行完整设计 DDL覆盖现有迁移库。

运行 API 使用 `/v1/` 前缀，任务幂等键目前在请求体，部分 Memory/Skill 操作使用 revision/状态机而不是设计中的所有操作统一 Idempotency-Key。运行表数量与完整设计48表不同。上述差异是阶段实现记录，不能把“设计51操作/48表”当成已交付数量。生产统一合同仍需后续验收。

`scripts/export_runtime_openapi.py` 从实际 FastAPI 导出；修改接口后重跑。历史设计检查82项等仅验证设计材料，不执行服务；实际应用测试有独立输出。新增文档链接会影响设计检查数量，不应固定宣传数量。

## 两种启动方式

### 完整 Docker

在根目录复制 `.env.example` 为 `.env`（已存在则保留），运行：

```powershell
docker compose -f infra/docker-compose.yml -f infra/compose.app.yml up -d --build --wait
docker compose -f infra/docker-compose.yml -f infra/compose.app.yml ps
```

应用地址 `http://127.0.0.1:8080`；API `http://127.0.0.1:8000/docs`；`/ready` 检查迁移版本与Redis，**不证明模型可用或知识内容已审核**。migrate 成功退出属于正常行为。

Compose 为 API/worker 使用容器服务名；为浏览器单独使用 `S3_PUBLIC_ENDPOINT=http://127.0.0.1:9000` 签名，防止把浏览器不可访问的 object-store 主机名写入URL。bucket 为私有、SSE请求及跨端口CORS均配置，已实测PUT；这不改变资产 pending 状态。

Docker 镜像仅带运行所需源码、原创研究草稿及语料清单，不复制Key、音频、备份或全量抓取库。原有大语料盘点来自 SUMMARY，不能据此认为镜像已装载这些内容。knowledge_working/indexes 命名卷保存实际研究包/索引清单。

### 本地编辑调试

Python3.12、Node24、Docker Desktop。根目录运行 `scripts/dev.ps1 setup`，随后三个终端分别运行 `scripts/dev.ps1 api`、`worker`、`web`。API8000、Vite5173。

`setup` 安装 Python 精确依赖快照、Node lock、启动基础设施、迁移、准备资料并配置私有存储CORS。API镜像已在Linux成功构建，soundfile wheel实测带有libsndfile。新机器首次安装需可访问相应镜像与包仓库。

已运行整套 Compose 时，先 `docker compose -f infra/docker-compose.yml -f infra/compose.app.yml stop api worker web`，保留基础设施，再启动本地进程。Windows checkpoint worker 使用 Selector event loop，直接运行 `python -m app.worker` 已处理；不要用不兼容事件循环包装它。

## 模型接入步骤

适配器支持兼容的 `/embeddings`、`/rerank`、`/chat/completions`。默认模型只是配置建议，未用真实Key确认账户权限。Key只放本地.env，禁用外部trace；模型失败返回脱敏错误。

提供Key后，先确认账户、模型、额度和D-007预算条件。当前仍缺货币硬预算/预占/结算，不应直接启用无人监管的付费运行。确认后本地执行 `python -m app.knowledge.cli prepare` 和 `python -m app.knowledge.cli ingest`；Compose 中对应 `docker compose -f infra/docker-compose.yml -f infra/compose.app.yml run --rm migrate python -m app.knowledge.cli ingest`。变更.env需重新创建API/worker；仅restart不会更新容器环境。

无Key时不会生成假向量或假回答，只显示资料预览。模型维度/语料/模式变更须重建索引；旧 manifest 不可继续使用。实体共现扩展不等于专家审核声乐知识图谱。

## CI与发布

GitHub Actions在push/PR运行Ubuntu PostgreSQL/Redis后端测试、Ruff、文档合同检查、有限凭据模式检查，以及前端npm ci/build。CI不启动Neo4j/Milvus或浏览器，这些由本地集成验收补充；不要把skipped测试计为通过。私有原始答卷不上传，CI显式 `--repository-only`，报告跳过3项本地私有来源核查。本机默认命令仍执行原始来源核查。

凭据检查只覆盖tracked文件中的有限模式，不是完整安全/依赖漏洞扫描。仓库保持私有。通过测试后提交、推送当前功能分支；云端结果需在每次推送后查看，不能以本地测试代替。

## 常见问题

- 端口8000被占用：先确认自己的本地API和Compose是否同时运行，不批量杀进程。
- 上传失败：核对浏览器Origin、RustFS CORS、public endpoint、SSE请求头；预签名URL属于临时凭据，不记录日志。
- 上传成功却不能测评：这是仅预签名的已确认边界；pending不能绕过校验。
- 页面任务完成但列表无产物：前端已修复轮询结束时cleanup中断列表刷新的竞态；后端任务与产物同事务落库。
- Docker语料状态500：已修复Python dict.get提前求值导致读取未打包normalized文件的问题；缺失/损坏元数据返回受控503。
- 记忆修改409：刷新revision重试；关闭/清除后不应让历史压缩任务恢复偏好。
- 修改.env后无变化：重建容器环境或重启本地进程，配置有进程级缓存。
- 外部包/镜像下载失败：保留数据卷，重试build；不要把网络失败当作应用测试通过。
- 全新检出后pytest临时目录报错：`_qa/`不进Git，CI和dev脚本必须先创建它；已按首次云端CI失败日志修正初始化，不能依赖开发机已有目录。
