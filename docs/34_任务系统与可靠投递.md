# 任务系统与可靠投递

更新日期：2026-11-04。当前仍为本地测试身份模式。

## 使用

执行 Alembic upgrade head，启动 Docker 的 PostgreSQL 和 Redis，然后运行 `python -m app.worker`（API 工作目录为 apps/api）。`--once` 处理一次调度周期，便于诊断。

`POST /v1/jobs` 接收 kind、input、可选 input_asset_id、必填 idempotency_key，返回 202。`GET /v1/jobs`、`GET /v1/jobs/{id}`、`POST /v1/jobs/{id}/cancel` 均从本地身份映射 owner。请求不能指定 owner。相同 owner 和幂等键复用相同任务；内容不同时返回 409。

assessment 必须引用本人 ready 资产。当前预签名上传保持 pending，因此真实上传的测评入口明确阻断，不能用手动改状态作为生产替代方案。其他任务处理能力以各处理器状态为准。evaluation 的 infrastructure 检查只验证队列基础设施，不代表声乐评估。

## 故障语义

任务和 outbox 同事务入库。投递器锁定未发布事件，Redis XADD 成功后标记 published；中间崩溃可能重复通知。Redis Streams 消费组和 XAUTOCLAIM 回收通知，数据库行锁与 lease/worker_token/version 阻止重复有效结果。PostgreSQL 定期扫描恢复丢失通知、延迟重试及超期任务，Redis 不是业务事实来源。

worker 使用实际 timeout_seconds 限制 handler 时间，租约额外保留 30 秒。完成 UPDATE 同时验证 owner、RUNNING、token、version、有效租约和未取消；旧 worker 的迟到结果被丢弃。取消即时转 CANCELLED 并撤销租约；已开始的外部计算可能继续一小段时间，但不能回写为成功。

仅明确可重试错误或超时进入指数退避，默认最多 3 次；未知异常终止，防止无限费用。最后一次崩溃由扫描转 FAILED。失败死信通过 outbox 持久记录后投递 Redis deepvocal:dead。当前长耗时音频应放入独立进程/适配器，不能阻塞事件循环。

## 验证

20 项测试通过（含 PostgreSQL 和隔离 Redis DB15 集成）：并发幂等、冲突键、outbox 原子性、重复通知、取消、owner 404、旧 worker fencing、租约回收、退避/耗尽、死信记录、最终尝试崩溃恢复和 pending 音频拒绝。

## 后续运维

任务结果只允许由当前 worker 写入。已确认只做本地身份，因此本阶段不是生产部署。Redis stream 历史裁剪、任务保留期限、进程资源隔离、外部服务幂等与监控告警需要在部署阶段补齐；不能将投递至少一次解释为外部工具执行严格一次。
