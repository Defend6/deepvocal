# 后续开发路线与未完成项

更新日期：2026-11-04  
当前分支：`feature/platform-skeleton`

本文记录当前工程骨架之后仍需完成的开发范围。接口占位、Mock 和文档设计不计为已实现能力；每个阶段应补充测试、运行记录和可回滚的 Git 提交。

## 已完成的工程基线

- FastAPI 服务、健康检查、确定性意图路由和 Agent 能力状态接口。
- React + TypeScript + Vite 工作台基础页面及 API 联调。
- Docker Compose 本地 PostgreSQL、Redis、RustFS、Neo4j、Milvus/etcd 基础设施。
- 首个 Alembic 核心迁移：users、audio_assets、jobs、outbox_events，并含跨用户资产复合外键约束。
- GraphRAG 数据准备目录和只读语料状态接口。当前数据为准备状态，接口明确阻止其作为生产语料。
- S3/RustFS 对象存储底层适配器：bucket 初始化、音频预签名上传、对象检查和删除。
- 本地调试身份与生产 OIDC/JWKS Bearer 校验、`issuer + subject` 用户映射和可信 owner 上下文；本地认证只允许 mock/development/test 模式。
- 音频资产预签名上传 API、owner 隔离、PostgreSQL pending/ready/invalid 状态、过期检查和 SHA-256 完成校验；上传完成不会自动创建测评任务。

## 当前数据集的边界

`datasets/` 是本地研究与准备数据，不等于可直接推送或部署的生产语料。现有来源中包括非商业和相同方式共享许可，仓库公开前必须逐项确认再分发条件。数据准备目录的状态接口是只读盘点，不会生成 embedding，也不会写入 Neo4j/Milvus。真实用户练声记录仍为 0，不得以合成记录代替真实用户证据。

## 建议推进顺序

1. 完成鉴权和所有者隔离，建立安全的用户上下文。
2. 完成对象存储上传和任务 API，再建设 outbox/Redis worker。
3. 形成 LangGraph Supervisor 和可测的四 Agent 子图合同。
4. 先做数据审核/导入流水线和知识问答评测，再接生产 GraphRAG。
5. 按录音诊断、全曲测评、练习规划次序补齐可验证能力。
6. 最后接入用户提供的歌声生成 API，并启用授权与滥用防护。

每个 P0/P1 阶段完成后，先跑对应自动化检查，更新本路线和实施记录，再提交并推送功能分支；经整体验收后再合并到 `main`。数据或密钥类文件不得因为功能提交而自动进入 Git。
