# 数据库迁移与本地基础设施迭代

日期：2026-11-04  
分支：`feature/platform-skeleton`

## 本次变更

- Docker Compose 已覆盖 PostgreSQL、Redis、RustFS（S3 兼容）、Neo4j、Milvus 与 etcd；对象存储镜像按 digest 固定。
- 当前开发机已有其他容器占用 5432/6379，DeepVocal 映射到 15432/16379，避免与其他项目共享端口或数据库卷。
- 增加 Alembic 异步数据库迁移框架和 `0001_core` 迁移，创建 users、audio_assets、jobs、outbox_events。
- jobs.input_asset_id 与 owner_id 使用复合外键，数据库拒绝任务跨用户引用音频资产。
- `.env.example` 的数据库和 Redis 地址同步到 DeepVocal 专用端口；真实密钥仍只放本地 `.env`。

## 已实现边界

本次只有核心事务实体的首个迁移，不代表 `database/schema.sql` 中其余设计表已经迁移或已对接 API。鉴权、对象上传、Redis worker、outbox 发布器、LangGraph 持久检查点仍待实现。当前迁移不启用 RLS；未来每个 repository 查询仍必须带可信 owner 条件。

## 验证

- `docker compose config --quiet`：通过。
- RustFS 容器健康检查：通过。
- PostgreSQL 集成检查通过条件：用 `TEST_DATABASE_URL` 指向隔离测试库，运行 `python -m pytest`；测试会执行迁移并验证跨 owner 资产引用遭拒。
- 推送前必须先完成 `gh auth login`，创建私有仓库并推送本分支；不得提交 `.env` 或用户/原始数据。

## 接续节点

1. 完成 PostgreSQL migration 与 owner 约束集成验证。
2. 实现 S3 兼容对象存储 presign adapter 和 bucket 初始化。
3. 实现数据库 outbox 到 Redis 的至少一次投递、幂等消费和失败恢复。
