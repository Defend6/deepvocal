# 身份认证与音频上传实现记录

日期：2026-11-04
分支：`feature/platform-skeleton`

## 身份边界

- `AUTH_MODE=oidc` 校验 Bearer JWT 的 RS256/384/512 签名、公钥 `kid`、issuer、audience、`exp` 和 `iat`；JWKS 地址由部署配置提供。
- 用户由 `(issuer, subject)` 唯一映射，API 从认证结果生成 owner ID。业务请求不接受客户端指定的 owner。
- `AUTH_MODE=local` 只允许 `DEEPVOCAL_MODE=mock/development/test`，并要求显式 `X-Debug-Identity: issuer|subject`。此路径仅用于本地验证，不提供生产安全性。
- `/v1/me` 用于验证身份映射。用户状态不是 active 时拒绝访问。

## 上传接口

### `POST /v1/uploads`

请求字段：`filename`、`content_type`、`size_bytes`、小写十六进制 `sha256`、`purpose`。API 创建 owner 专属对象 key 和 `pending` 资产，再返回限时预签名 PUT URL 与必须原样发送的 headers。

签名绑定 Content-Type、AES256 服务端加密、SHA-256 checksum 和 SHA-256 元数据。客户端应对原始文件计算 SHA-256，并在 PUT 时发送响应中的全部 `required_headers`。

### `POST /v1/uploads/{asset_id}/complete`

服务端只查询当前 owner 的资产，并用行锁串行化完成请求。pending 资产需在有效期内存在；HEAD 必须匹配声明大小、MIME、S3 原生 SHA-256 checksum 及 sha256 元数据。成功后设置 `ready` 和完成时间。再次完成 ready 资产返回原结果；其他 owner 看见 404。校验不匹配时标记 invalid 并尝试删除对象。

上传完成只确认音频资产，不会触发诊断、全曲测评或其他任务。任务须由后续显式任务 API 创建。

## 数据库与运维

迁移 `0002_uploads` 为 `audio_assets` 增加 `upload_expires_at`、`completed_at` 和 pending 过期扫描索引。后续清理 worker 应扫描过期 pending 记录，重试清理对象并按策略归档状态；当前尚未提供 worker。

生产部署必须设置 `DEEPVOCAL_MODE=production`、`AUTH_MODE=oidc`、`OIDC_ISSUER`、`OIDC_AUDIENCE` 和 `OIDC_JWKS_URL`。API 进程需要能访问 JWKS。对象存储签名 URL 由服务端根据 `S3_ENDPOINT` 生成，开发浏览器需要能访问该 endpoint；生产环境应使用浏览器可达的同域/网关地址，并配置 CORS 允许 PUT 和所需的 checksum/encryption/metadata headers。RustFS 的 SSE-S3 必须配置 `RUSTFS_SSE_S3_MASTER_KEY`；Compose 默认值仅供本地开发，生产必须注入独立的 base64 32-byte secret。

本阶段不包含登录 UI/会话管理、OIDC discovery 自动发现、下载 URL、音频解码内容探测、过期对象清理 worker、任务创建 API。若 OIDC 服务商要求 ES256/EdDSA 或非标准 claim 映射，需按真实 issuer 元数据扩展允许算法与 claim 规则，不得关闭签名验证。
