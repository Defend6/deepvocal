# 身份认证与音频上传实现记录

日期：2026-11-04

分支：`feature/platform-skeleton`

## 当前实施范围

按用户补充选择，本阶段仅实现本地测试身份与音频预签名 URL。之前提交中的 OIDC/JWKS 校验、上传完成回调和对象完整性校验已在后续提交撤下。原 Git 历史保留，已应用的数据库迁移不回滚。

## 本地身份

- `AUTH_MODE=local` 只允许 `DEEPVOCAL_MODE=mock/development/test`。
- 每次访问 `/v1/me` 或 `/v1/uploads` 必须发送 `X-Debug-Identity: issuer|subject`；缺失或格式错误返回 401。
- 调试身份由调用者自行声明，只用于本地开发，不是可信的生产认证。owner 隔离用于测试不同身份的数据归属，不能阻止本地调用者冒充其他调试身份。
- 用户按 `(issuer, subject)` 映射，服务端生成 owner ID。上传请求不允许指定 `owner_id`，账户非 active 时拒绝访问。
- `OIDC_ISSUER`、`OIDC_AUDIENCE`、`OIDC_JWKS_URL` 和时钟偏差参数仅保留配置位；目前没有 Bearer/OIDC 处理能力，`AUTH_MODE=oidc` 会启动失败。生产部署需在后续完成真实认证后再启用。

## 预签名上传

`POST /v1/uploads` 接收 `filename`、`content_type`、`size_bytes`、小写十六进制 `sha256` 和 `purpose`。API 创建 owner 专属随机对象 key 和 pending 资产记录，返回 `asset_id`、`object_key`、`upload_url`、`required_headers`、`expires_in`。

客户端使用 PUT 上传原始文件，原样发送返回的 Content-Type 和 AES256 加密请求头。文件名不用于构造对象 key。声明的大小和 SHA-256 只保存到数据库，未核验实际对象；申请参数大小校验不等于限制 PUT 的真实字节数。

本阶段没有 `/v1/uploads/{asset_id}/complete`，不执行 HEAD 完成校验、不标记 ready、不创建测评任务。PUT 成功仅说明对象存储收到数据；数据库资产仍保持 pending，不能当作经过校验的业务输入。

## 数据库与运行

已应用的 `0002_uploads` 迁移及其 `upload_expires_at`、`completed_at`、pending 扫描索引保留。`completed_at` 在当前流程中不写入。申请时记录的业务过期时间是未来清理流程的数据准备；当前只由签名 TTL 限制 URL 有效期，没有自动扫描/删除 worker。

RustFS SSE-S3 需要 `RUSTFS_SSE_S3_MASTER_KEY`，Compose 默认值仅用于本地开发。对象存储 endpoint 必须能由上传客户端访问；浏览器上传仍需 CORS 配置和后续前端流程。
