# 声学测量与练习闭环（实际实现）

更新：2026-11-04。代码版本 mono-autocorrelation-v1，评分规则 engineering-v1，规划规则 practice-template-v1。所有分数是工程练习参考，未经过声乐教师评级校准，不判断医学问题或发声原因。

## 输入与真实能力

支持 libsndfile 可解码的音频，100 MiB、0.1～600秒、1～2声道、8～192kHz；超大解码分配提前拒绝。选择能量较强声道后重采样16kHz，避免反相双声道平均成静音。自相关 F0 范围65～1100Hz，64ms窗口、20ms步长。能量和周期性门槛固定随算法版本管理。伴奏、多声部、噪声、混响不属于可靠测量范围，当前没有自动伴奏分离及专业音质分类器，不能把 quality=usable 解读为证明没有干扰。

- free_singing：发声时长、音域、跟踪覆盖；没有参考不能提供音准/节奏准确率及综合分。
- long_tone：提交前明确 goal_duration_ms；整个目标窗口覆盖至少0.8、有效跟踪至少3秒、录音覆盖目标时长才出分。3秒整录音可能因分析窗边界不足3秒有效跟踪而不给分，建议任务录制4秒以上。MAD稳定性和最长连续有效发声比例按24章计算，无插补空洞。
- reference_song：用户提交已展开、秒级参考音符，固定用户选择的offset/移调/有界速度；不自动寻找最高分移调。按有效帧时长累计 cents，参考时长加权起音误差；覆盖、八度错误、休止误发声同时输出。超过0.3秒不匹配起音；重复同音无清晰重新起音可能不出节奏及总分。当前是固定时间轴近邻起音匹配，不是可靠自动曲目对齐器。

质量失败不给分，缺维度不重分配权重；LLM不能改分。全部数值有限，输出Python基础类型，避免检查点序列化失败。输出包括算法/规则/对齐版本、可用原因及分段覆盖。

## 离线复算和现有数据

在根目录：`.venv\Scripts\python -m app.audio_cli <本地音频> --config <任务JSON> --output D:\deepvocal\_qa\report.json`（先安装 apps/api）。配置示例：`{"profile":"long_tone","goal_duration_ms":4000}`。CLI只读显式本地文件，不提供服务器任意文件读取接口，不导入业务资产。

`scripts/benchmark_audio.py` 读取已有vocadito ZIP及F0标注，校验音频SHA256；对齐最近标注帧、不跨无声区插值，报告带无声漏检惩罚的50cents原始音高准确率。2026-11-04本机40段音频宏平均0.928392，结果在忽略的 `_qa/audio-benchmark.json`。这是现有外语清唱的离线算法核查，不是独立留出验证、中文曲目正确率、发声问题诊断或教师评分准确率；未做克隆、训练或原音频再分发。

## 任务与业务事务

assessment worker 只读取同owner的ready资产，有限读取对象后重新核对大小和SHA256。按用户确认的“仅预签名URL”范围，当前HTTP上传资产一律pending，**没有完成回调，也不会自动ready**；因此浏览器新上传音频不能进入测评。真实声学内核可用离线CLI核查；集成测试通过明确的测试ready资产、模拟对象读取，验证完整LangGraph到报告流程。这不代表浏览器测评闭环已开放。

报告及计划只在worker持有有效令牌、版本、租约且未取消时，和任务SUCCEEDED同一数据库事务创建。source_job_id唯一，不因重复通知创建两份；取消或失去租约的旧worker不能发布报告/计划。报告不可编辑；计划以version乐观锁编辑，冲突409，保留休息块且每日5～30分钟。

规划可根据用户目标、分钟数、天数和自选本人报告创建工程模板；不从报告推断病因或自动加大强度。无报告明确标明基础模板。反馈由用户真实提交，包含计划版本、实际时长、难度、不适和备注；幂等键避免重复记录。当前反馈用于回顾，不代表已具备长期疗效预测或自动自适应课程。

## 歌声生成

D-014当前仅预留能力接口。无外部服务协议，不构造虚假生成结果；始终明确disabled，即使误设开关也不声称可用。后续须确定服务协议、明确授权与生成确认后再启用实际调用。

## 验证范围

合成音测试覆盖反相双声道、静音、削波、短时长、参考八度错误、漏唱和结构化输入。真实PostgreSQL/LangGraph测试覆盖计划创建、owner隔离、版本冲突、幂等反馈、取消阻止业务落库和资产内容哈希不符。没有用测试中的合成信号充当生产测评数据。
